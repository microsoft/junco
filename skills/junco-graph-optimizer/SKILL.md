description: Optimize an existing Junco workflow's graph topology through measured restructuring, decomposition, tournaments or pruning, not new-workflow creation or model, scheduler or limit tuning.
---

Rewrite the selected `<workflow>.yml` in place with confirmed geometry; change its prepared TS only for audited geometry-required bindings. Read [references/optimization.md](references/optimization.md) before preparation or experiments; its complete procedures are mandatory.

## Preserve

- Keep models, thinking, all five ordered ladder rungs and strength selection/escalation unchanged, along with scheduler algorithms/composition and every limit's value, scope and enclosing enforcement boundary.
- New geometry inherits effective model/strength, scheduling, window/threads and limits explicitly at every level; parent strength is not recursive. If policy, measurement windows, readiness or ownership cannot be preserved through bindings alone, report the candidate inapplicable.
- Keep authoritative evaluators/checks, assignment text, helper bodies, contracts, tools and permissions fixed; new agents receive no broader access. Concurrent workers require already-safe independent artifacts.
- Require explicit paid-run authorization. Never fabricate prerequisites or measurements; synthetic/offline evidence proves wiring, not savings. Never call `schedules.runOptimizer` or the `junco-profile-optimizer` binary, copy their controller or write another.
- Never overwrite outside edits: precheck both target files before staging/restoring either; report conflicts without overwriting either.
- Consult the [standard library index in junco's root AGENTS.md](../../AGENTS.md#standard-library-index) before inventing replacement topology or helper code. Prefer indexed building blocks whose contracts fit the allowed transformation and prepared runner; reuse never permits changing frozen schedulers, adding unrequested persistence, bypassing reserved helpers or weakening the evaluator.

## Workflow

1. Inspect the pair, invocation, bindings, evaluator and repeat safety. Ask only unresolved [intake](references/optimization.md#inspection-and-intake); report missing prerequisites rather than inventing substitutes.
2. Preserve originals in the safe session; prepare dormant baseline instrumentation and reserved maps once, offline-check it, save immutable `prepared.ts` and baseline `incumbent-0.yml/.ts`, then check and measure only as authorized.
3. Derive each trial from the same saved incumbent pair: one geometry change, archived YAML and TS, plus an old→new binding audit for any TS difference. Stage the matched archived pair safely and set `expectedTsSha256` from its archived TS bytes.
4. Rank costly/difficult work using profiles and failure evidence. Consider [leader/workers, authoritative Ralph loop and two-candidate tournament](references/optimization.md#recipes), and a duty-proven [redundant-node ablation](references/optimization.md#redundant-node-ablation); report every inapplicable pattern.
5. Offline-check changed TS, run `measure.ts check`, then authorized `measure.ts run <name> <R>`. Accept quality-first; ablations also require strictly lower recorded USD. Freshly confirm the exact archived winning pair before promotion; re-profile afterward.
6. After owned child resources are gone, restore/retain the confirmed pair on rejection, failed confirmation, cancellation or stop. Without confirmed improvement, retain the original graph. Follow reference target/plateau/budget rules with no hidden cap; report the actual stop reason, never a global optimum.

## Report

Give baseline/final metrics, decisions, stop reason, retained paths/hashes, `prepared.ts` hash, binding changes and evidence/spend coverage using the reference's complete [report checklist](references/optimization.md#report).
