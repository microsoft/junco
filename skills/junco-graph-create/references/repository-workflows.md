# Repository-derived workflows (Trail/graft)

The outer topology comes from a Trail map at run time, so it is built with `graph.JuncoGraph.map` in TypeScript, not authored as YAML. Nested revision work still uses YAML: `parse(workflows.ralph, { params: { model } })` + `build(...)`. Read `typescript-api.md` for the `graph`/`agent`/`schedules` signatures used below.

## Repository-derived workflows

Apply only to repository work. Requirements: Bun, working Trail CLI (persisted GraphV1; verified with Trail 0.23.0), resolvable `junco-agency`/`ngraph.graph`. Missing prerequisites stop acquisition; no fallback graph, implicit installation, `--deep`, `--lsp` or agent/global setting changes.

1. **Refresh.** Resolve the user's target (or checkout Git root) to an absolute path. For new and existing repos run `trail build <absolute-repo> --no-gitignore --no-ignore` before selection. This map-only build avoids `trail init` agent wiring/history ingestion. Check exit status **and per-file diagnostics**: Tier-1 parse errors can exit 0. Failed selected-scope parsing blocks topology claims and work. Emit `trail build <repo> --no-gitignore --no-ignore && bun run <workflow.ts>` for later runs too; imports MUST NOT spawn Trail or initialize agents.
2. **Select.** Use the map's exact IDs and explicit path/symbol scope, not ranked top-N or guessed line IDs. Whole-repository tasks include all mapped file nodes and monorepo scopes. Use source-relative paths, signatures and summary/crux for assignments. Exclude exact in-target workflow/helper artifact paths to prevent self-rewriting. Empty selection reports `No matching repository definitions` before acquisition. `loadGraftGraph(repo, selectedIds)` reads `.trail/cache/.graph/wiring.json`, then legacy `graft/.graph/wiring.json`; a broken/unsupported existing preferred map fails, never falls back. Changed IDs require rebuild/re-authoring.
3. **Bundle unchanged.** Copy `scripts/graft.ts` bytes beside the workflow; import `./graft.ts`. Reuse an identical sibling; a differing `graft.ts` selects `./<workflow-stem>.graft.ts`. If that also conflicts, stop with the path; MUST NOT overwrite user code. Do not rewrite/specialize the parser, import installed-skill/checkout/private Trail paths, parse Markdown or federate workspaces. The helper covers one repo/scopes, preserves metadata/directed dependency links, excludes containment, and retains unresolved external edges as context without phantom nodes.
4. **Define the synchronous factory.** Author `f: (metadata: GraftMetadata) => graph.nodes.AgenticNode` with concrete non-chat message/result types and full specs, not casts. Mechanics → `graph.nodes.Deterministic`; language/judgment → `agent.JuncoAgent`; requested fixed full-answer revision → a pre-acquired child scheduler context from `parse(workflows.ralph, { params: { model } })` and `await build(doc, { cwd, models, tracer: observer, scheduler: () => schedules.parallel(), ...schedules.ralph({ rounds }) })` (requested rounds, otherwise omit for two). Return `{ ...nodeOptions, state: childContext }` from the synchronous mapper, with no own spec-level policy. Enqueue the complete task+metadata prompt exactly once on the child's explicit `assignment` source route before registration, or configure and wire explicit parent-edge ingress as described above; code-neighbour edges do not assign work. Multi-stage/repeat-until work uses a child context with real Source/Sink ports and the task's stop condition. No blanket Ralph selection or extra reviewer/retry/cap. Share the verified ModelRuntime/observer with children; never stage Ralph's worker prompt yourself.
5. **Assign finite outer work.** Give each role one complete task+metadata assignment with `graph.trigger.TriggerRule.always()`. The controller checks empty `all` and combines region admission with original availability. Regions are components after removing true bridges in the **undirected dependency multigraph**, not weak components; parallel/reverse edges and self-loops survive. Source→target bridge direction defines precedence; cycles remain communication/context topology. Put task fan-in/feedback/custom triggers inside children; bind contracts and explicit routing. Code edges do not forward results/start prompts. Update a generation-local completed-report map only at successful checkpoints; first-activation assignment callbacks may read validated predecessor reports. Route nested data through scheduled Source/Sink, never policy callbacks.
6. **Define validation before acquisition.** Implement `validate(region,results)` with task behavior and targeted repo commands; require valid reports, never model/prose self-approval alone or an assertion-only node. If no executable assertion is derivable, report the missing criterion before acquisition. Intermediate checks are region-scoped; whole-repo assertions run before the final checkpoint when `completedReports.size + region.nodeIds.length === topology.skeleton.getNodeCount()`. After one context `step()` decision, the controller checks every member by map membership (undefined results count), awaits validation/progress once, and admits successors only after all predecessors pass, not merely a bridge endpoint. Failure stops downstream work without retry/success reporting; unfinished quiescence errors. After validation, drive real remaining sink work, never fabricate output. Checkpoints are run-local, not durable resume/commits.
7. **Acquire, map, drive.** Pre-acquire definition-ID→full-spec entries, awaiting all Ralph `build` calls and preparing their explicit assignment ingress before mapping; track each resource immediately, including workers before child composition. `f` MUST NOT return a promise or acquire child contexts. Acquisition/mapping failures close every acquisition while preserving the construction error; `JuncoGraph.map` leaves partial members caller-owned. Use fresh explicit `$source`/`$sink`: closed Source rejects scheduled ingress; Sink waits on the task-selected terminal and returns its exact retained result, not an inferred last node. For whole-selection completion, gate on all required native final-value edges. Call `const workflow = graph.JuncoGraph.map(topology.skeleton, metadata => checkpoints.gate(metadata,f(metadata)), { source,sink,policy,tracer })`; wire real work to `workflow.graph.sink`. Drive only `await checkpoints.run(workflow)`, not direct graph execution/tracer callbacks. Close `workflow.graph` in `finally`, flush in nested `finally`, then close outer collections/member session repositories; shared agents stay open through last use. The controller never closes/flushes the caller's graph. Empty topology invents no work/checkpoint/result.
8. **Report passed boundaries.** Share explicit `new tracer.DummyTracer()` by default. Supply async-capable `progress(checkpoint)`; update completed reports from its region-only stable `results` snapshot. Print `Checkpoint <k>/<regions> passed: <region ID> (<nodes>/<total> nodes validated)` using `completedRegions`, `totalRegions`, `region.id`, `completedNodes`, `totalNodes` (selected outer nodes, not original map/nested counts). Final output follows closure/flushing. Requested TUI tracing uses `log.info` from `junco-tools/log` with INFO-admitting `LOG_LEVEL` (default INFO), never stdout/stderr during terminal ownership. Reporting stays in the callback, not graph-algorithm I/O.

Helper exports: `GraphMetaV1`, `GraftMetadata`, `GraftEdge`, `GraftRegion`, `GraftTopology`, `GraftCheckpoint<T>`, `parseGraftGraph(value, selectedIds?)`, `loadGraftGraph(repoRoot, selectedIds?)`, `graftCheckpoints<N, T>(topology, { validate, progress })`. Controller: `gate(metadata, fullSpec)`, `run(workflow)`. Inspect bundled readonly metadata/callback types; preserve additional same-version fields, null enrichment and pending/stale summaries.
